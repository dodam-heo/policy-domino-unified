# 정책도미노 통합 재구축 — 최종 실행 정의

> **제품 목표**: 법률·시행령·시행규칙·훈령·예규·고시·지침 등 공식 정책의 변경이 **어느 공공기관의 어떤 실제 사업·업무·서비스·시스템 기준을 어떻게 바꾸게 하는지** 검증 가능한 출처와 함께 제시한다.
>
> 대상 조직: 중앙행정기관·지방자치단체·교육청·공공기관. 민간조직 및 기관의 조치 완료 여부 판정 제외.

## 자산 사용 판단

- **v2**: 보존된 JSON 데이터와 유효한 공식 수집·추출·연도별 비교 알고리즘의 *검증 대상*. v2 화면은 UI 통합 참조 제외.
- **policy-domino**: 현재 수집·의미 비교·법령 의존관계·기관 후속조치 분석과 화면 기능을 검증 대상으로 사용. 원본 불변.
- **policy-domino-next**: 공식 색인·법령 연관·정부24·ALIO+·의미 설명과 화면 기능을 검증 대상으로 사용. 원본 불변.
- **unified**: 단일 저장/분석/출판 엔진. 기능별로 개선·교체한다. 원본 소스를 무작정 복제하지 않는다.

## 증거 상태 계약

| 단계 | 정의 | 승격 조건 |
|---|---|---|
| 색인 발견 | 공식 ID·일련번호·제목·발령일 확보 | 공식 목록에 근거. 이전 파일에서 온 색인은 `historic_index_only` |
| 추출 기록 | 판본별 본문·조문·별표 텍스트 보존 | 이 단계만으로 완전 공식 원문이라고 하지 않음 |
| 공식 원문 검증 | 국가법령정보 원본 XML과 해시·본문/첨부 검증 | `official_original_verified` |
| 실질 변경 검증 | 종전과 신본 양측 검증, 실제 조문·기준 차이 | `official_comparison_verified` |
| 관련 규정 연결 | 정확한 변경 조항/항의 인용·적용 | 관련 규정의 공식 증거, 인용만으로 기관 수정 의무 판정 금지 |
| 공공사업 연결 | 공식 사업명·담당기관·실제 운영기준 및 법적 적용관계 | 직접·2단계 연결은 별도의 검증 등급 유지 |
| 기관별 후속조치 | 실제 어떤 기준·안내·절차·업무가 달라져야 하는지 | 수치 변경과 사업 종전 기준의 일치 등 근거 필요. 이행 완료 여부 판정 안 함 |

**중요**: 기존 46,647건 보유판본 **목록 감사 완료**와 862건 **추출본 재사용 후보**를 공식 원문 전수 검증으로 해석하지 않는다. 충돌 24건은 원문 재검증 대상이다.

## 시스템 데이터 흐름

1. 기존 수집 데이터로부터 **메타데이터만** `data/indexes/legacy/{source}/{shard}.json.gz`에 1회 승계. 최초 GitHub Actions 실행에서 pinned snapshot으로 이관.
2. 공식 원천에서 날짜/규정 종류/연혁별 목록을 수집하고 독립 색인 파일과 조사 구간 완결성·실패를 기록.
3. 원문을 `data/documents/<source>/<stable_hash>/<version_hash>.json.gz`에 버전별 불변 저장. 첨부 원본은 콘텐츠 해시로 보존.
4. 신구 비교는 `data/comparisons/`에 별도 보존. 연도별 제정 고시도 이전 연도 같은 운영기준을 찾아 비교하되 정확한 이전 판본이 불명확하면 미검증.
5. 변경 조항 ↔ 적용 규정 ↔ 공식 공공사업을 증거 그래프로 추적. 직접 증명한 업무 변경과 법률적 연관성만 있는 검토 후보를 구별.
6. `data/impacts/`에 기관별 검토 자료를 보관. AI는 증거를 보강해 설명하되 기관·사업·금액 등을 창작하지 않음.
7. `site/data.json`은 **검색/목록용 경량 색인**, `site/details/<hash>.json`은 **클릭 시 가져올 개별 상세**로 분리.
8. `site/acceptance.json`과 `site/data.json.quality`에 원천 누락·검증 미완료를 공개. GitHub Actions는 배포 성공과 제품 수용검사 통과를 구분.

## UI 계약

현행 domino와 domino-next의 장점을 통합하되 새 데이터 계약을 기준으로 다시 구현한다.

- 왼쪽 최신순 **정책 변경 목록**: 신규/개정/폐지, 법적 자료 종류, 정책 분야는 각각 다른 차원. 분석 대기 자료도 조회.
- 상세 최상단 **변경 핵심과 시행일**: 실제 종전→현행 문구의 핵심 발췌; 불완전하면 그 상태 표시.
- **영향 공공기관·사업**: 기관명 필터, 공식기관 유형별 계층, 사업명과 검증 수준. 기관의 이행 완료 여부 표시 금지.
- **사업별 변경 조치**: 해당 업무/기준, 종전 값과 새 값, 변경 조문, 서비스 공식 근거.
- 하단 **추가 신구 비교·전체 원문·관련규정·첨부**: 긴 텍스트는 접기.

## 테스트·출시 조건

1. 과거 두 코드베이스의 원천 버전 데이터가 누락 없이 이관되고 재검증 대상과 확정 원문 구분.
2. 실제 국가법령정보 API에서 법령·고시·행정규칙·자치법규의 전체 탐색 경로가 동작하며 누락 구간이 성공으로 둔갑하지 않음.
3. 별표·PDF·기타 공고 원문의 표와 금액은 출처 기반으로 추출. 미추출 스캔/이미지 값은 단정 금지.
4. **2027년 기준 중위소득·주거급여·교육급여** 공식 문서의 색인→본문→전년도 기준 비교→기관별 조치→화면 **전 단계 검증**. 특정 고시명은 수집 코드에 고정하지 않음.
5. 복지·교육·환경·금융·조직·산업 등 임의 표본도 동일한 테스트 적용.
6. 이름만 비슷한 기관/사업, 다른 조문·항 인용, 숫자만 우연히 같은 기준을 오연결하지 않을 것.
7. 소스 파일 100MB 제한, 동시 데이터 작성, 문서 원문 훼손, 화면 표시 데이터 손실 방지.
8. 수집 결과가 실패하면 저장 상태를 설명하고, 실질 원문·업무 영향이 검증되지 않으면 녹색 출시 판정을 주지 않는다.
9. 실제 모바일·데스크톱에서 필터→정책 상세→기관/사업→후속조치→출처 클릭의 전체 사용자 경로 확인.

## 이번 PR의 정확한 상태

**개발 착수/기초 통합 구현**: 추출본 신뢰도 정정, SHA 기반 원본 검증, 과거 판본 메타데이터 이관 경로, 연도별 전판 후보 검색, 직접/2단계 관계 분석, 보수적 기관후속 검증, 경량 목록/상세 분리, 개편 UI, 회귀 품질 보고 및 PR 테스트.

**아직 미검증 / 출시 차단 사유**: 공식 API 재수집 성공, 과거 전체 원천 이관 실행, 연도별 고시 별표·표 수치 원문 대조, 실데이터 기반 기관 조치 실증, 실제 모바일 브라우저 UX 승인. 통과 전에는 PR을 draft로 둔다.

운영 저장소 두 곳은 변경하지 않으며, PR 병합 전 별도 코드·데이터·실사용 검증을 거친다.
